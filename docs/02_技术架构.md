# 技术架构设计

> 架构师：梁政 ｜ 版本 V1.0 ｜ 本文档回答"为什么这么选"（面试要能讲）。

## 1. 总体架构

```
浏览器（React前端）
   │  REST API
   ▼
FastAPI 后端
   ├── routers/       薄路由（只做校验+转发）
   ├── ai/            大模型适配层（DeepSeek，可切换）
   ├── rag/           切片/向量化/检索（模块A）
   └── models.py      数据模型
   │
   ├── SQLite（业务数据）      └── chromadb（向量）
```

三层结构：前端展示 / 后端业务 / 数据存储。AI 调用统一走适配层，换模型只改一处。

## 2. 选型理由（面试必答）

| 选型 | 为什么 |
|------|--------|
| FastAPI | 轻量、类型友好、AI 生成稳定、自带 OpenAPI 文档 |
| SQLite | 零运维，MVP 够用；ORM 已抽象，生产可切 MySQL |
| 向量检索（numpy+SQLite） | 本机 Windows 上 chromadb HNSW 索引跨进程加载异常，故自实现余弦相似度；数千切片毫秒级；可平滑迁移 chromadb/Milvus |
| DeepSeek API | 便宜、中文强；走 OpenAI 兼容接口，可无缝切换 |
| React + Vite | 主流、组件生态全（AntD）、面试通用 |

## 3. 目录结构

```text
backend/app/
├── main.py            # 入口：注册路由、启动初始化

│   ├── llm.py         # DeepSeek 封装：chat()、超时、重试

└── rag/
    ├── splitter.py    # 文档切片
    ├── embedder.py    # 向量化入库（chromadb）
    └── retriever.py   # 检索 TopK
```

## 4. 数据流示例（面试讲数据流）

**模块A 问答：**
```
用户提问 → /api/kb/ask → 向量化问题 → chromadb 检索TopK
        → DeepSeek(检索片段+问题, 提示词=只依据片段作答)
        → 返回 answer + sources[]
```

**模块B 纪要：**
```
粘贴文字稿 → /api/meeting/parse → DeepSeek(固定四段提示词)
        → 存 meetings 表 → 返回结构化Markdown
```

**模块C 客户：**
```
Excel → /api/customer/import → openpyxl 读 → 清洗 → 入库
文本 → /api/customer/extract → DeepSeek(JSON提示词) → 入库
查询 → /api/customer/search / /api/stats/dashboard
```

## 5. 数据模型

```python
documents:  id, title, file_type, created_at
kb_chunks:  id, doc_id, chunk_text           # 向量在 chromadb 里按 doc_id 关联
meetings:   id, title, transcript, summary, decisions, todos, created_at
customers:  id, name, company, phone, email, source, notes, created_at
```

## 6. 提示词规则（架构师定的约束）

- 知识库问答：只依据检索片段作答，答不出就直说，禁止编造，必须带来源
- 会议纪要：固定四段 Markdown（摘要/关键决定/待办事项/发言要点）
- 客户提取：只输出 JSON，缺省填"未提供"
- 全部：temperature=0.2，中文，超时30s，失败重试2次
