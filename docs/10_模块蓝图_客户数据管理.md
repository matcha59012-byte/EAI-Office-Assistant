# 模块蓝图 V2：客户数据管理（阶段3）

> 版本 V2.0 ｜ 2026-08-18 ｜ 状态：执行中
> V2 变更：客户实体**复用"信息提取"模块的实体层**（实习期CRM方案 格式卡片），本模块专注**管理/跟进/告警/看板**；不再自建一套客户表。
> 严格遵循：AGENTS.md 铁律（按模块、测试3遍、不编造、技术栈锁定）、地基卡、docs/13 反思（先学习、模板即验收、玻璃三栏）。

---

## 1. 定位

客户实体库：把"信息提取"确认归档的**客户/项目/公司卡片**集中管理，支持搜索、跟进、静默告警、看板；可 Excel 导入、手动新增、编辑。

## 2. 功能清单

| 功能 | 说明 |
|------|------|
| 实体库列表 | 客户/项目/公司三类，按类型切换 + 搜索 + 状态筛选 |
| 详情查看 | 实习期CRM方案 格式 md 卡片（复用信息提取 card_md） |
| 编辑卡片 | 修改字段 + status/last_contact |
| 跟进管理 | status（新/跟进中/静默/已关闭）+ last_contact 一键更新 |
| 静默告警 | 超 30 天未跟进客户 → 告警清单（排除已关闭） |
| 看板统计 | 总数/状态分布/来源分布/静默数 |
| 数据来源 | ①信息提取确认的卡片自动进入 ②Excel 导入 ③手动新增 |
| 三方关联 | 客户↔项目↔公司 关联查看/跳转 |

## 3. 数据模型（扩展现有 entities 表）

```
entities（复用信息提取实体层）
  + status        # 跟进状态：新 / 跟进中 / 静默 / 已关闭（默认 新）
  + last_contact  # 最后联系日期 YYYY-MM-DD（可空）
```

## 4. API 设计

```
GET  /api/customer/entities?type=&status=&q=     # 列表（默认 customer）
GET  /api/customer/entities/{id}                 # 详情
PUT  /api/customer/entities/{id}                 # 编辑（字段 + status/last_contact）
POST /api/customer/entities/{id}/follow          # 记录跟进（last_contact=今天, status=跟进中）
POST /api/customer/import                        # Excel 导入（name 必填，跳过重复）
GET  /api/customer/alerts                        # 静默告警（>30天未跟进 且 status!=已关闭）
GET  /api/customer/dashboard                     # 看板：总数/状态分布/来源分布/静默数
```
