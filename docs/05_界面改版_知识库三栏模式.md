# 知识库界面改版设计（Obsidian/实习期项目 三栏对话模式）

> 版本 V1.0 ｜ 状态：待评审 ｜ 改版范围：模块A（知识库问答）界面与交互
> 本设计只描述"改什么、怎么改、分几步"，**不修改任何代码**，评审通过后按步骤实施。

---

## 1. 现状与问题诊断

| 你的反馈 | 现状 | 根因 |
|---------|------|------|
| ①"每次提问完才展示窗口" | 提问后弹出一个结果卡片，打断感强 | 是"一问一答"表单，不是"对话流" |
| ②"要像 Obsidian/实习期项目 三栏：右边AI问答、中间看文档、只能查看不能增删改" | 现在是：上传+文档表格+提问，没有"看文档内容"的能力 | 没有文档查看器，也没有三栏布局 |
| ③"要有历史，能基于之前继续提问，不能每次刷新" | 每次提问无历史、无会话，页面不保留上下文 | 后端无会话/消息存储，前端无状态 |

**改版核心**：把模块A从"上传→表单→结果卡"改成 **"文档库(中栏) + AI对话(右栏) + 会话历史"** 的办公形态。

---

## 2. 目标形态（三栏布局）

```
┌─────────┬──────────────────────┬─────────────────────┐
│ 左侧导航  │   中栏：文档区(只读)    │   右栏：AI 问答区      │
│         │                      │                     │
│ 知识库   │  · 文档列表（只读）     │  · 会话历史（可新建/切换）│
│ 会议纪要 │  · 点击文档 → 查看内容  │  · 对话消息流（滚动）    │
│ 客户数据 │  · 不支持增删改         │  · 输入框（Enter发送）  │
│         │                      │  · "基于当前文档提问"    │
└─────────┴──────────────────────┴─────────────────────┘
```

- **左栏**：现有模块导航（知识库/会议纪要/客户数据）
- **中栏**：只读文档库——员工像看知识库一样浏览文档内容
- **右栏**：AI 问答工作台——会话历史 + 对话流，可基于中间打开的文档提问

---

## 3. 功能需求（含验收标准）

| 编号 | 功能 | 说明 | 验收标准 |
|------|------|------|---------|
| F1 | 对话流问答 | 消息在对话区依次追加，提问后不刷新页面 | 连续问3个问题，对话区呈"一问一答"纵向列表 |
| F2 | 会话历史 | 可新建/切换/删除会话，切换后回到该会话历史 | 新建2个会话，各自保存，可切换回看 |
| F3 | 文档查看（只读） | 中栏列文档，点开显示内容；无上传/删除按钮（员工视角） | 点文档显示全文；页面无"上传/删除"入口 |
| F4 | 基于当前文档提问 | 中栏打开的文档 → 右栏提问限定在该文档内检索 | 打开"考勤制度"问"迟到怎么处理"，来源只来自该文档 |
| F5 | 上下文续聊 | AI 带最近 N 条历史回答，能接上"上一个问题" | 先问"报销要什么材料"，再问"那多久内提交"，AI能关联 |
| F6 | 角色控制 | 员工只读；上传/删除仅管理员（轻量实现） | 员工视角无增删改；后台仍保留接口 |
| F7(可选) | SSE 流式 | AI 回答打字机式输出，体验像 DeepSeek/实习期项目 | 回答逐字出现 |

## 4. 后端改动方案

### 4.1 新增数据模型

```python
chat_sessions(id, user_id=1, title, created_at)      # 会话
chat_messages(id, session_id, role[user/assistant], content, created_at)  # 消息
```

> 暂无登录系统：先固定单用户 `user_id=1`，后续加登录再改。

### 4.2 新增/调整 API

```
GET    /api/kb/sessions                  # 会话列表
POST   /api/kb/sessions                  # 新建会话 {title?}
DELETE /api/kb/sessions/{id}             # 删除会话
GET    /api/kb/sessions/{id}/messages    # 会话消息历史
POST   /api/kb/sessions/{id}/messages    # 在会话中提问
       # body: {question, doc_id?}  doc_id 表示"基于该文档提问"
       # 返回: {answer, sources[], rejected}
GET    /api/kb/documents                 # 只读文档列表（保留）
GET    /api/kb/documents/{id}/content    # 新增：文档全文内容
POST   /api/kb/upload                    # 保留（仅管理员调用）
DELETE /api/kb/documents/{id}            # 保留（仅管理员调用）
```

### 4.3 会话上下文（F5）

提问时把**最近 6 条消息**拼进 LLM 提示词，让 AI 能接上下文；超过 6 条只取最近的（控制 token）。

### 4.4 文档范围检索（F4）

`POST .../messages` 带 `doc_id` 时，检索只查该文档的切片（chromadb `where: {doc_id}`），确保答案来源限定在当前文档。

### 4.5 拒答规则不变
相似度 < 0.45 仍直接拒答，不靠模型自觉。

## 5. 前端改动方案

### 5.1 组件划分（右栏做成可复用组件，供模块B/C复用）

```
frontend/src/
├── components/
│   ├── ChatPanel.tsx      # 右栏：会话列表+消息流+输入框（复用）
│   └── DocViewer.tsx      # 中栏：只读文档列表+内容查看
└── pages/
    └── KnowledgePage.tsx  # 三栏整合：左导航 + DocViewer + ChatPanel
```

### 5.2 状态管理
- `sessions` / `currentSessionId` / `messages`
- `docList` / `currentDoc` / `docContent`
- 提问后把 user 消息和 assistant 回答 append 到当前消息流，不刷新页面

### 5.3 交互细节
- 中栏点文档 → 加载内容展示 + 自动带出"基于当前文档提问"开关
- 右栏输入 Enter 发送（Shift+Enter 换行）
- 会话可重命名/删除（删除需确认）

## 6. 分步实施计划（每步测试3遍，通过才进下一步）

| 步骤 | 内容 | 验收 |
|------|------|------|
| 步骤1 | 后端：会话+消息数据模型 & 4个会话API | 冒烟测试：建会话/发消息/回读历史/删会话 |
| 步骤2 | 后端：文档内容接口 + 文档范围检索（doc_id） | 打开文档能取到全文；限定文档问答来源正确 |
| 步骤3 | 后端：会话上下文（历史拼进提示词） | 连续追问能关联上下文 |
| 步骤4 | 前端：ChatPanel 组件（会话列表+消息流+输入） | 三栏骨架 + 对话流可用 |
| 步骤5 | 前端：DocViewer 组件（只读列表+内容查看） | 点文档看内容，无增删改 |
| 步骤6 | 前端：三栏整合 + 当前文档提问 + 构建 | 全链路走通，页面体验接近 Obsidian |
| 步骤7(可选) | SSE 流式输出 | 回答打字机效果 |

> 步骤4-6 前端联调时，中栏文档查看也可先复用"知识库问答"做过渡。

## 7. 风险与注意

| 风险 | 应对 |
|------|------|
| 文档"只读"是前端隐藏，接口仍在 | 轻量角色开关：`.env` 加 `APP_IS_ADMIN=true/false`，非管理员调用 upload/delete 返回 403（步骤6一并做） |
| PDF 预览复杂 | 第一版显示抽取的文本，PDF 原版渲染后续再做 |
| 会话历史很长，token 超限 | 只取最近6条拼提示词 |
| 多用户 | 先固定单用户，接口已预留 user_id 字段 |

---

## 8. 一句话结论

把模块A从"表单问答"升级为 **"Obsidian式三栏：只读文档库 + AI对话工作台 + 会话历史"**，后端加会话/消息存储与文档查看接口，前端拆出可复用的 ChatPanel，分 7 步实施、每步测试3遍。
