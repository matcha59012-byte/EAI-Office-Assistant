## 一、模块B：智能会议纪要（阶段2）

### 1.1 定位与价值
把"会议记录文字稿"一键变成结构化纪要：**摘要 / 关键决定 / 待办事项 / 发言要点**。
面试亮点：这是传统企业最疼的痛点，且你已经踩过（实习转写29份录音）。

### 1.2 已就绪资产（无需重写）
| 资产 | 位置 | 说明 |
|------|------|------|
| 提示词模板 | `backend/app/ai/prompts.py` → `MEETING_SYSTEM` | 固定四段输出，已锁定 |
| 数据模型 | `backend/app/models.py` → `Meeting` | 字段齐：transcript/summary/decisions/todos |
| 聊天组件 | `frontend/src/components/ChatPanel.tsx` | `sessionScope="meeting"` 直接复用 |

### 1.3 功能设计
```
左栏：会议记录历史列表（新建/查看/删除）
中栏：文字稿输入区（粘贴）→ AI 生成四段纪要（md 渲染）→ 保存
右栏：复用 ChatPanel（可选，基于会议内容/知识库问答）
增强（后加）：上传录音 → ASR 转写 → 再走纪要流程
```

### 1.4 API 设计
```
POST /api/meeting/parse      # {transcript, title?} -> 结构化四段（不保存）
POST /api/meeting/records    # {title, transcript, summary, decisions, todos} -> 保存
GET  /api/meeting/records    # 历史列表
GET  /api/meeting/records/{id} # 详情
DELETE /api/meeting/records/{id}
```

### 1.5 分步实施（每步测试3遍）
| 步骤 | 内容 | 验收 |
|------|------|------|
| B1 | 后端：`/api/meeting/parse`（LLM 四段 + 无Key降级） | 粘贴文字稿返回四段 |
| B2 | 后端：records 增删查 | 保存后列表/详情正常 |
| B3 | 前端：会议纪要页（左历史 + 中输入/结果 + 右ChatPanel复用） | 全流程网页可操作 |
| B4 | 全链路测试 3 遍 + 文档同步 | 3/3 通过 |

## 二、模块C：客户数据管理（阶段3）

### 2.1 定位与价值
把散在 Excel/文本里的客户信息 → AI 提取/清洗 → 统一台账 → 搜索 + 看板。
面试亮点：贴合你3年采购成本数据管理经验（前公司台账），且有"数据治理"含金量。

### 2.2 已就绪资产
| 资产 | 位置 | 说明 |
|------|------|------|
| 提示词模板 | `prompts.py` → `CUSTOMER_EXTRACT_SYSTEM` | 只输出 JSON，已锁定 |
| 数据模型 | `models.py` → `Customer` | 字段齐：name/company/phone/email/source/notes |
| Excel 解析 | `openpyxl`（依赖已装） | 导入用 |
| 看板 | antd 图表（后续按需引入，或简单统计卡片） | — |

### 2.3 功能设计
```
左栏：导入（Excel） + 搜索框
中栏：客户表格（分页） + 详情
右栏：文本 AI 提取区（粘贴文本→提取客户字段入库）+ 看板统计卡片
```

### 2.4 API 设计
```
POST /api/customer/import      # Excel 上传 -> 字段映射入库（去重）
POST /api/customer/extract     # {text} -> LLM 提取 {name,company,phone,email,notes}
GET  /api/customer/search?q=   # 模糊搜索
GET  /api/customer/{id}        # 详情
GET  /api/stats/dashboard      # 总数/来源分布/时间分布
DELETE /api/customer/{id}
```

### 2.5 分步实施（每步测试3遍）
| 步骤 | 内容 | 验收 |
|------|------|------|
| C1 | 后端：`/api/customer/import`（Excel→入库，含去重） | 导入后列表可见 |
| C2 | 后端：`/api/customer/extract` + search + dashboard | 文本提取正确、搜索命中、看板有数 |
| C3 | 前端：客户数据页（导入+表格+搜索+看板+AI提取） | 全流程网页可操作 |

## 三、共同要点

1. **复用 ChatPanel**：`sessionScope` 已支持 kb/meeting/customer，会话按模块隔离。
2. **无 Key 降级**：两个模块都做"未配置 DeepSeek Key 时诚实降级"（纪要=展示文字稿原文分段；客户=展示原始文本）。
3. **安全**：会议纪要、客户数据不进知识库向量（不污染"演示知识库"资料库），数据在各自表内。
4. **拒答/防编造**：沿用提示词规则（只依据输入内容，禁止编造）。
5. **企业真实数据 IP 提醒**：测试用脱敏/自造示例数据，不用真实客户/会议数据。

## 四、执行顺序
阶段2（会议纪要）B1→B4 全绿后，再启动阶段3（客户数据）C1→C4。两个模块互不依赖，可并行，但按规则逐个推进、逐个验收。
