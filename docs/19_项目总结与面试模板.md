## 一、项目总结（架构师版）

### 1. 一句话定位

**用 FastAPI + React 自研一个"可检索、可提取、可问答"的企业 AI 办公助手**：把传统企业散落的制度文档、会议记录、客户数据，变成带来源可追溯的 AI 知识资产。

### 2. 开发背景

- **业务痛点**：传统企业员工仍停留在"用豆包网页版"的 AI 水平——制度文档靠翻、会议纪要靠人肉整理、客户情况靠翻 Excel，数据散落、检索困难、无法沉淀。
- **目标岗位**：AI 应用 / 数字化 / 大模型应用方向。要求作品可部署、可现场演示、面试能讲清"业务→架构→规则→验收"。
- **项目来源**：在实习期三个项目（客户数据管理系统、会议录音智能转写、企业知识库检索系统）基础上合并演进，产品化为统一平台。
- **开发方式**：本人担任**架构师**，锁定技术栈/目录/数据模型/接口/提示词规则/验收标准（`地基卡.md` + `AGENTS.md`），代码由 AI 按规则生成、本人负责读懂、校验、验收——Vibe Coding 协作模式。
- **项目周期**：2026.02 - 2026.08，按模块分 3 个阶段开发，每阶段独立验收（测试三遍铁律，3 遍全过才算完成）。

### 4. 开发功能（三大模块）

#### 模块 A · 企业知识库问答（RAG）
- 文档上传（txt/md/pdf/docx）→ 段落/句子切片 → bge 向量化入库；
- 提问 → 向量化 → 余弦检索 TopK → DeepSeek 按"只依据检索片段作答"生成 → 返回答案 + 可点击跳转的来源；
- **确定性拒答**：相似度 < 0.45 直接拒答（实测校准：合法问题最低 0.47 / 无关最高 0.43），不靠模型自觉；
- **金标评估集**：自动回归"问题→期望来源"，命中率 90%（10 篇演示文档 9/10，阈值 ≥80%）；
- 资料库（文件夹）隔离：按 library 字段限定检索范围；
- 会话历史落库，上下文续聊（最近 6 条拼入提示词）；
- 演示知识库载入 10 篇虚构通用制度文档，检索毫秒级响应。

#### 模块 B · 智能会议纪要 / 信息提取（自生长闭环）
- 源文件管理（txt 自动转 md / MP3→MiMo ASR 转写）；
- R1 文本清洗（Speaker→人名、修拼写、去废话、标 [UNCLEAR]）；
- R2 三路提取（一次 prompt 同时出客户/项目/公司实体卡片，含行事风格 5 维、9 问、A/B/C 准入预筛）；
- R3 增量 diff（对比已有实体，标记 🆕新增 / 🔄更新）；
- **人工确认闭环（AI提取人工确认原则：AI 提取、人决策）**：确认时可编辑卡片再入库，防止错误信息污染；
- 增量不覆盖：同名实体 merge，已有字段有值不覆盖；
- 实体卡片 = 实习期CRM方案 格式 md（职业/画像/行事风格/行动指南/关联/语录 分区），来源可追溯。

#### 模块 C · 客户数据智能管理 + 实体问答
- 实体库列表 / 搜索 / 筛选 / 状态切换 / 跟进 / Excel 导入；
- 静默告警：last_contact 超 30 天且未关闭自动进告警清单；
- 看板统计 + 项目时间轴（AI 填 start_date/end_date_est，前端算进度百分比）；
- **实体问答（灵魂功能）**："张三什么情况？" → 卡片向量化检索 TopK + 关联展开（关联项目/公司卡片）→ DeepSeek 汇总归属公司/参加项目/进度/需求，附来源跳转；
- 前端三栏玻璃 Splitter 布局 + Obsidian 式 md 编辑二级窗口（macOS 交通灯+毛玻璃+动效）。

## 三、面试模板

### 模板 1 · 30 秒自我介绍（开门见山）

> 您好，我叫梁政，软件工程本科应届，曾在幕墙公司做数字化/AI 提效实习，把 AI 落地到真实业务。这半年我独立架构并完成了一个"企业 AI 智能办公助手"：三个模块——知识库 RAG 问答、会议信息提取、客户实体问答，技术栈是 React + FastAPI + DeepSeek + 向量检索。我在里面做架构师，定架构、定规则、定验收，AI 按规则写代码我来校验。做完这套系统，我最大的体会是：**AI 的价值不在模型本身，而在把业务规则、工程可靠性、人工决策设计进系统里。**

### 模板 2 · STAR 结构化叙事（2 分钟版）

- **S（背景/痛点）**：传统企业制度文档靠翻、会议靠人肉整理、客户靠翻 Excel，数据散落无法沉淀，员工只会用豆包网页版。
- **T（任务）**：做一个可部署、可演示的 AI 办公平台，把三类数据变成"可检索、可提取、可问答"的知识资产；同时要"可信"——答不出的不编造、提取的人确认、质量用数字衡量。
- **A（行动）**：定技术栈（React+FastAPI+SQLite+DeepSeek+bge 向量检索）、定三层架构、定提示词规则与拒答阈值、定验收标准；按模块分 3 个阶段交付，每模块测试 3 遍。自己动手解决两个硬坑：chromadb 索引崩溃→自实现 numpy 向量检索；react-markdown 清洗 doc:// 协议→关闭 urlTransform。
- **R（结果）**：三大模块全部可运行；演示知识库 10 篇文档毫秒级检索、评估集命中率 90%；会议整理从小时级到分钟级；客户查询一句话出总结。

### 模板 3 · 高频问答（背诵版）

**Q：为什么用 FastAPI 不用 Django/Flask？**
轻量，本项目是 API 服务不是全栈；类型提示友好（Pydantic），AI 生成代码也稳定；自带 OpenAPI 文档，前后端联调方便。

**Q：为什么用 SQLite 不用 MySQL？**
MVP 零运维、单机够用；我用 SQLAlchemy 做了抽象，换 MySQL 只改连接串。"先用最简单的存储跑通、留好扩展口"是务实的工程决策。

**Q：向量检索为什么自实现，不用 chromadb？**
先用过 chromadb，但 Windows 上大量写入后跨进程加载 HNSW 索引崩溃（1.5.9 和 0.5.23 都复现）。改成 sentence-transformers(bge-small-zh) 向量化 + numpy 余弦 + SQLite BLOB 存向量，几千条毫秒级返回；接口已抽象，数据量上来可平滑迁移 chromadb/Milvus，只改 store.py。

**Q：怎么防止 AI 编造（幻觉）？**
三层防护：①确定性拒答——相似度低于 0.45 直接返回"未检索到"，不调模型，从根上堵住"没资料硬编"；②提示词规则——只依据片段作答、片段没有就直说；③来源标注——回答带可追溯来源。阈值 0.45 是实测校准的：合法问题最低 0.47、无关问题最高 0.43。

**Q：怎么保证检索质量？**
建了金标评估集：从资料库抽取文档生成"问题→期望来源"，自动脚本跑检索，命中率 90%（10 篇演示文档 9/10，阈值 ≥80%）。每次改检索逻辑都回归一遍，用数字说话，不靠感觉。

**Q：为什么提取结果要人工确认？**
这是"AI提取人工确认原则"：AI 提取，人决策。AI 只做 80% 的重复工作，20% 的关键决策（信息对不对、要不要入库）交给人，防止错误信息污染知识库。确认时还能直接编辑卡片再入库。

**Q：增量不覆盖怎么实现？**
确认入库时同名实体做 merge：已有字段有值就保留，只有空缺才补新值，避免 AI 每次提取覆盖人工修正过的内容。

**Q：实体问答"问张三什么情况"怎么实现？**
把客户/项目/公司卡片 md 向量化→问题向量化检索 TopK→关联展开（把关联的项目/公司卡片一起取出）→DeepSeek 按"基于卡片总结、不编造"规则生成→返回结构化总结+来源卡片可点击跳转。

**Q：你印象最深的坑？**
三个：①chromadb 跨进程索引崩溃→自实现 numpy 向量检索；②react-markdown 默认清洗 doc:// 未知协议导致点击刷新页面→关闭 urlTransform 并拦截点击；③Excel 导入列号 0 在 Python 里是 falsy，`col.get("姓名") or ...` 漏判第一列→改成显式判断。

**Q：AI 写代码，你不怕出问题吗？**
我定"地基卡"：技术栈、目录、数据模型、接口、禁止事项全锁定；AI 每次只做一个小功能，交付必须带运行命令，我跑通验收才继续；测试三遍铁律。关键是定好规则并建立校验能力，而不是让 AI 自由发挥——这正是 Vibe Coding 的主流协作方式。

**Q：项目怎么测试的？**
每个模块有冒烟测试脚本（httpx 全接口跑通），每条功能连续测试 3 遍全过才算完成；检索质量另有金标评估集。前端 tsc + vite build 保证类型和编译通过。

**Q：后续规划？**
①部署上线（Docker + 云服务器）；②SSE 流式回答（打字机效果）；③Electron 打包桌面版；④换数据源快速复用成制造/医疗/教育等行业的问答与信息管理系统。
