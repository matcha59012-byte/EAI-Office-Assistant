# E-AI Office Assistant：项目面试问答表

> 版本 V1.0 ｜ 2026-08-18 ｜ 用途：面试前背诵/演练。**回答原则：架构师视角、先结论后细节、用数字、诚实标注未做项。**

## 一、项目介绍类

### Q1：介绍一下你的项目
> 我给传统企业做了一个"AI 智能办公助手"，三个核心能力：
> 1. **知识库**：上传制度/流程文档，AI 用 RAG 检索后带来源回答，答不出的直接拒答，不编造；
> 2. **信息提取**：把会议纪要（或 MP3 转写）用 AI 提取出客户/项目/公司实体卡片，**人工确认后才入知识库**，形成自生长闭环；
> 3. **客户数据**：实体库管理 + 静默告警 + 看板 + 项目时间轴，以及**实体问答**——直接问"张三什么情况"，AI 汇总他的公司/项目/进度/需求。
> 技术栈是 React + FastAPI + SQLite + DeepSeek。我担任架构师，负责定架构、规则和验收，代码由 AI 按我的规则生成、我负责校验。

### Q2：你这个项目解决了什么痛点？
> 传统企业员工普遍还停留在"用豆包网页版"的 AI 水平：不懂 API、不懂规则、把 AI 当万能工具。项目把 AI 能力产品化落地：
> ①知识库让制度文档"能问"且**带来源可信**；②会议信息从"人肉整理"变成"AI 提取 + 人确认"；③客户信息从"散落 Excel"变成"可检索可问答的实体库"。

### Q3：你在这个项目里扮演什么角色？
> 架构师 + 验收人。我定了：技术栈选型、三层架构、数据模型、提示词规则、拒答阈值、验收标准；AI 按这些规则写代码，我负责读懂、跑通、校验、上线。这正好是现在 Vibe Coding 的主流协作方式。

## 二、技术选型类

### Q4：为什么用 FastAPI 不用 Django/Flask？
> ①轻量，本项目是 API 服务不是全栈；②类型提示友好（Pydantic），AI 生成代码也稳定；③自带 OpenAPI 文档，前后端联调方便。

### Q5：为什么用 SQLite 不用 MySQL？
> MVP 零运维、单机够用；我用 SQLAlchemy 做了抽象，换 MySQL 只改连接串。对面试加分：**"先用最简单的存储跑通，留好扩展口"** 是务实的工程决策。

### Q6：向量检索怎么做的？为什么没用 chromadb？
> 选型时确实先用了 chromadb，但在 Windows 上**大量写入后跨进程加载 HNSW 索引崩溃**（1.5.9 和 0.5.23 两个版本都复现了）。我改成自实现：用 sentence-transformers（bge-small-zh）做向量化，**numpy 算余弦相似度，SQLite BLOB 存向量**，几千条数据毫秒级返回。接口抽象好了，数据量上来可平滑迁移 chromadb 或 Milvus，只改 store.py。

### Q7：中文向量模型为什么选 bge-small-zh？
> 中文效果好、模型小（约 95MB）、本地推理免费、无额外 API 费用。对比 all-MiniLM 英文模型对中文支持差。

### Q8：为什么用 DeepSeek？为什么不本地部署大模型？
> ①便宜、中文强、走 OpenAI 兼容接口可无缝切换；②本地部署 7B+ 模型在 8GB 显卡上效果和速度都不行，得不偿失。**大模型是调用方，价值在工程落地，不在自己训练/部署。**

## 三、知识库 / RAG 类

### Q9：RAG 完整流程讲一下
> 上传文档 → 按段落/句子切片 → bge 向量化 → 存向量库；提问 → 向量化 → 余弦检索 TopK → 把检索片段拼进提示词 → DeepSeek 按"只依据片段回答"的规则生成 → 返回答案 + 来源，来源可点击跳转原文。

### Q10：怎么防止 AI 编造（幻觉）？
> 三层防护：
> ①**确定性拒答**：检索相似度低于 0.45 直接返回"未检索到"，不调用模型，从根上堵住"没资料硬编"；
> ②**提示词规则**：只依据片段作答、片段里没有就直说；
> ③**来源标注**：回答带引用来源，可追溯。阈值 0.45 是实测校准的：合法问题最低 0.47，无关问题最高 0.43，中间取阈值。

### Q11：怎么保证检索质量？
> 我建了**金标评估集**：从演示资料库抽取文档生成"问题→期望来源"，自动脚本跑检索，命中率 90%（10 篇演示文档 9/10，阈值 ≥80%）。每次改检索逻辑都跑一遍，用数字回归，而不是靠感觉。

### Q12：会话怎么做到上下文续聊？
> 会话和消息落库，提问时把**最近 6 条消息**拼进提示词作为历史上下文，同时限定"历史只用于理解，回答仍以当前检索片段为准"。

### Q13：资料库（文件夹）隔离怎么做的？
> documents 表加 library 字段；问答时先解析该库的文档 id 集合，检索只在这些 id 里查（向量检索支持 doc_id 集合过滤），实现"只在这个资料库里问"。

## 四、信息提取 / 实体提取类

### Q14：信息提取的 R1-R3 是什么？
> 借鉴了我实习做过的 实习期CRM方案 CRM 方案：
> R1 清洗（Speaker→人名、修拼写、去废话、标 UNCLEAR）→ R2 三路提取（一次 prompt 同时出客户/项目/公司卡片）→ R3 增量 diff（对比已有实体，标记🆕新增/🔄更新）。

### Q15：为什么提取结果要人工确认？
> 这是"AI提取人工确认原则"：**AI 提取，人决策**。AI 只做 80% 的重复工作，20% 的关键决策（"这条信息对不对、要不要入库"）交给人，防止错误信息污染知识库。确认时还能直接编辑卡片再入库。

### Q16：实体卡片为什么要用 Markdown 存？
> ①可读、可编辑（Obsidian 风格直接改 md）；②结构化字段（JSON）用于列表/检索，md 用于展示/编辑，两者结合；③面试上这是"结构化 + 半结构化结合"的务实设计。

### Q17：增量不覆盖怎么实现的？
> 确认入库时，如果同名实体已存在，做 merge：**已有字段有值就保留，只有空缺才补新值**。避免 AI 每次提取覆盖人工修正过的内容。

### Q18：MP3 转写（ASR）方案？
> 复用我实习项目 实习期项目 的方案：ffmpeg 抽单声道 16kHz → MiMo ASR 转写 → DeepSeek 做说话人区分 + 术语纠错 → 输出带 Speaker 的会议纪要。大文件按 300 秒分段、段间等 30 秒防限流。（诚实：当前 key 待配置，代码已就绪）

## 五、客户数据 / 实体问答类

### Q19：实体问答怎么实现"问张三什么情况"？
> 把客户/项目/公司卡片的 md 内容向量化 → 问题向量化检索 TopK → **关联展开**（把该客户关联的项目/公司卡片也一起取出）→ DeepSeek 按"基于卡片总结、不编造"的规则生成 → 返回结构化总结 + 来源卡片可点击跳转。

### Q20：静默告警怎么算？
> 客户 `last_contact` 距今超过 30 天且状态不是"已关闭"，就进告警清单；看板显示静默数。跟进时一键更新 last_contact 和状态。

### Q21：项目时间轴怎么实现？
> 提取时让 AI 填 `start_date/end_date_est` 结构化字段；前端按 `(今天-开始)/(结束-开始)` 算进度百分比，用进度条显示"未开始/进行中/已到完工"，当前日期自动推算。

## 六、工程与协作类

### Q22：你遇到的印象最深的坑？
> 三个：
> ①chromadb 跨进程加载索引崩溃 → 自实现 numpy 向量检索；
> ②react-markdown 默认会把 `doc://` 这种未知协议清洗成空链接，点击直接刷新页面 → 关闭 urlTransform 并拦截点击实现来源跳转；
> ③Excel 导入列号 0 在 Python 里是 falsy，`col.get("姓名") or ...` 会漏判第一列 → 改成显式判断。

### Q23：你和 AI 怎么协作开发？"AI 写代码你不怕出问题吗"？
> 我定"地基卡"：技术栈、目录结构、数据模型、接口、禁止事项全锁定；AI 每次只做一个小功能，交付必须带运行命令，我跑通验收才继续；**测试三遍**铁律。所以我"能对 AI 输出负责"——关键是定好规则并建立校验能力，而不是让 AI 自由发挥。

### Q24：项目怎么测试的？
> 每个模块都有**冒烟测试脚本**（httpx 全接口跑通），每条功能连续测试 3 遍全过才算完成；检索质量另有金标评估集。前端 `tsc + vite build` 保证类型和编译通过。

### Q25：后续规划？
> ①部署上线（Docker + 云服务器）；②SSE 流式回答（打字机效果）；③Electron 打包成桌面版；④知识库与企业真实业务更深结合（需脱敏/授权）。
