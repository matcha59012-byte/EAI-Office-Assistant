## 一、重置演示数据（部署前必做，已是纯虚构）

> 演示数据来自 `backend/sample_data/`：10 篇虚构「XX科技有限公司」通用制度文档 + 1 篇虚构会议转写稿 + 1 份虚构客户 Excel。不含任何真实公司/人名/项目信息。

| # | 动作 | 说明 |
|---|------|------|
| 1 | **一键重置数据库** | `python scripts/seed_demo_data.py`：清空全部业务表并导入 10 篇演示文档（自动向量化），输出导入清单 |
| 2 | **确认无真实数据** | 重置后 `documents` 仅含 `sample_data/` 的 10 篇文档，`entities`/`meeting_sources`/`customers` 为空 |
| 3 | **上传演示素材（可选）** | 上传 `sample_data/演示素材/演示会议_XX科技项目排期讨论.md`、导入 `sample_data/演示素材/演示客户数据.xlsx`，完成三模块演示数据 |
| 4 | **删除 .env 敏感项** | 部署版 .env 只保留 `DEEPSEEK_API_KEY`；`MIMO_ASR_API_KEYS` 不填（ASR 不用就不暴露 key） |

**重置命令**（本地跑一次即可，之后随代码一起部署）：
```bash
cd backend
.venv\Scripts\activate
python scripts/seed_demo_data.py
```

> ⚠️ 红线：`.gitignore` 已锁定 `sample_data_company/`、`sample_data_demo/`、`*.db`、`.env`，任何真实数据一旦出现会立刻被 git 拒绝提交；部署前建议再跑一次 `python scripts/scan_sensitive.py` 检查敏感词命中数 = 0。

## 四、部署步骤（方案A 操作手册）

### 第1步：数据清洗（见第一节，必做）
### 第2步：本地准备虚构案例
- 知识库：清空后用 `sample_data/` 4 篇虚构文档重新上传（或直接 seed）
- 信息提取：上传 1 篇虚构会议纪要 → 提取 → 确认入库（做出演示数据）
- 客户数据：导入虚构 Excel → 有几条客户，看板有时间轴数据

### 第3步：环境配置（部署版）
```bash
# backend/.env
DEEPSEEK_API_KEY="你的key"
APP_IS_ADMIN=false        # 访客只读，隐藏上传/删除/编辑入口
# MIMO_ASR_API_KEYS 留空（不暴露）
```

### 第4步：前端只读化确认
- 知识库：`APP_IS_ADMIN=false` 时上传/删除已隐藏 ✅
- 信息提取：上传/扫描/编辑/确认按钮需**改为仅管理员可见**（部署版访客看不到）
- 客户数据：编辑/状态切换/导入 → 同样仅管理员可见
> ⚠️ 这一步需要在代码里给"信息提取、客户数据"的写操作按钮加上管理员判断（类似知识库已做）。**部署前必须完成，否则访客可改数据。**

### 第5步：Docker 打包
```dockerfile
# Dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY backend/requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY backend /app/backend
COPY frontend/dist /app/backend/static      # 前端构建产物
WORKDIR /app/backend
EXPOSE 8000
CMD ["uvicorn","app.main:app","--host","0.0.0.0","--port","8000"]
```
- 后端 main.py 增加"托管前端静态文件"（FastAPI StaticFiles 挂载 /，SPA 回退）
- `docker build -t eai-office .`

### 第6步：部署到服务器
```bash
# 服务器（Ubuntu）：
docker pull python:3.11-slim
# 上传项目（不含 sample_data_company/ 等敏感目录）
scp -r EAI-Office-Assistant root@服务器IP:/opt/eai-office
# 服务器上：
cd /opt/eai-office
docker build -t eai-office .
docker run -d --name eai-office -p 8000:8000 \
  -e DEEPSEEK_API_KEY="你的key" -e APP_IS_ADMIN=false \
  -v /opt/eai-office/data:/app/backend/data \
  eai-office
```
（正式用 docker-compose 更好：后端 + 数据卷；前端已并入静态托管）

### 第7步：域名 + 备案（国内）
- 备案前：可用 IP+端口临时演示（`http://服务器IP:8000`），但 80/443 需备案才能解析
- 备案流程：买域名 → 云厂商备案（约1-2周）→ 绑定解析

### 第8步：安全加固
- 反向代理 Nginx + HTTPS（免费 Let's Encrypt）
- `.env` 不入镜像（用 `-e` 环境变量注入）
- 数据库放数据卷，不随镜像发布

## 五、面试演示脚本（部署后）

| 顺序 | 操作 | 讲解点 |
|------|------|--------|

## 六、风险清单

| 风险 | 应对 |
|------|------|
| 真实数据泄漏 | 部署前清洗（第一节）+ 清理本地敏感文件 |
| 访客篡改数据 | `APP_IS_ADMIN=false` + 写操作按钮管理员判断（第4步） |
| DeepSeek key 泄漏 | 用环境变量注入，不入代码/镜像/前端 |
| 国内访问慢/被墙 | 用国内轻量云，不用 Vercel |
| 备案耗时 | 先用 IP:端口 临时演示，备案期间不误事 |
| 前公司发现 | 全虚构案例 + 不上传任何真实资料 + 域名/标题不含公司名 |
