> 版本 V1.0 ｜ 2026-08-18 ｜ 作者：梁政（架构师）
> 本文档是项目技术层面的完整解说，供面试讲解与复盘使用。**所有描述与当前代码一致，未完成项已如实标注。**

---

## 1. 项目定位

给传统企业用的 **AI 智能办公助手**，三大能力：
- **知识库**：文档上传 → RAG 检索 → 带来源的 AI 问答（传统企业员工"豆包层"没这能力）
- **信息提取**：会议纪要/音频 → AI 提取客户·项目·公司实体卡片 → 人工确认 → 入知识库（自生长闭环）
- **客户数据**：实体库管理 + 跟进/静默告警/看板/项目时间轴 + **实体问答**（"张三什么情况"→ AI 汇总）

一句话：**把传统企业散落的文档和数据，变成"可检索、可提取、可问答"的 AI 知识资产。**

## 2. 整体架构

```
┌─────────────────────────────────────────────────────┐
│ 前端：React 18 + Vite + Ant Design 5（macOS 玻璃风）  │
│  知识库页 / 信息提取页 / 客户数据页（三栏 Splitter）    │
└──────────────┬──────────────────────────────────────┘
               │ REST API（Vite dev 代理）
┌──────────────▼──────────────────────────────────────┐
│ 后端：FastAPI + SQLAlchemy 2 + SQLite                │
│  ├ routers/   kb.py  chat.py  meeting.py  customer.py│
│  ├ ai/        llm.py(DeepSeek适配层)  prompts.py     │
│  │            asr.py(MiMo)  cards.py(实体卡md渲染)    │
│  └ rag/       splitter  embedder  store  qa          │
└──────────────┬──────────────────────────────────────┘
┌──────────────▼──────────────────────────────────────┐
│ 数据层                                               │
│  SQLite：documents/kb_chunks/chat_sessions/chat_      │
│          messages/meeting_sources/entities/           │
│          pending_extracts/customers                   │
│  kb_vectors：自实现 numpy 余弦向量检索（BLOB 存储）    │
└──────────────────────────────────────────────────────┘
```

**三层架构**：前端展示 / 后端业务 / 数据存储。AI 调用统一走适配层，换模型只改一处。

## 3. 技术栈选型及理由（面试必答）

| 层 | 选型 | 理由 |
|----|------|------|
| 前端 | React 18 + Vite + AntD 5 | 主流、组件生态全、类型安全；玻璃质感用 CSS `backdrop-filter` 实现，无额外 UI 库 |
| 后端 | Python 3.11 + FastAPI | 轻量、类型提示、自带 OpenAPI 文档、AI 生成代码稳定 |
| ORM | SQLAlchemy 2 | 数据库访问抽象，可平滑切 MySQL |
| 数据库 | SQLite | 零运维，MVP 够用；接口层已抽象 |
| 向量检索 | 自实现 numpy 余弦 + SQLite BLOB | **踩坑决策**：chromadb 在 Windows 大量写入后跨进程加载 HNSW 索引崩溃（1.5.9/0.5.23 均复现），改为轻量实现，毫秒级、零依赖、可靠；可平滑迁移 chromadb/Milvus（store.py 是唯一改动点） |
| 向量模型 | sentence-transformers bge-small-zh | 中文效果好、本地推理免费，走 hf-mirror 下载 |
| 大模型 | DeepSeek API（deepseek-chat） | 便宜、中文强；OpenAI 兼容接口 |
| ASR | MiMo ASR（api.xiaomimimo.com） | 复用实习期 实习期项目 的成熟方案（⚠️ key 待配置） |
| 编辑器 | @uiw/react-md-editor | Obsidian 式 Markdown 编辑，MIT |

## 4. 三大模块技术详解

### 4.1 知识库（RAG 问答）

```
上传文档(txt/md/pdf/docx) → 切片(段落→句子) → bge 向量化 → kb_vectors
提问 → 向量化 → 余弦检索 TopK → DeepSeek 按提示词回答 → 答案带来源
关键设计：
- 强制拒答：相似度 < 0.45 直接拒答，不靠 LLM 自觉（确定性规则，实测校准：合法问题最低0.47/无关最高0.43）
- 金标评估集：从演示资料库抽取文档生成"问题→期望来源"，自动脚本跑检索，命中率 90%（10 篇 9/10，阈值 ≥80%）
- 资料库（文件夹）隔离：library 字段，问答可按库检索
- 会话历史：chat_sessions/chat_messages，上下文续聊（最近6条拼入提示词）
- 来源跳转：答案末尾附 doc:// 链接，点击跳中栏文档（关键坑：react-markdown 默认清洗未知协议会把 doc:// 清成空导致页面刷新，需关闭 urlTransform）
```

### 4.2 信息提取（自生长闭环，借鉴 实习期CRM方案）

```
源文件(txt自动转md / MP3→MiMo ASR→md)
  → R1 文本清洗（Speaker→人名、修拼写、去废话、标[UNCLEAR]）
  → R2 三路提取（一次prompt：客户/项目/公司卡片，含行事风格5维、9问、A/B/C准入）
  → R3 增量 diff（🆕新增/🔄更新 标记）
  → 人工确认（AI提取人工确认原则：AI提取，人决策；可编辑卡片后再入库）
  → 实体层入库（实习期CRM方案 格式 md 卡片，来源可追溯）
  → 扫描闭环（源文件夹新文件自动进待确认队列）
关键设计：
- 实体卡片 = md 文档（职业/画像/行事风格/行动指南/关联/语录 分区），可 Obsidian 式编辑
- 增量不覆盖：重名实体 merge，已有字段有值不覆盖
- 准入预筛：A/B/C 级，C 级客户/公司自动跳过
- 提示词规则化：日期 YYYY-MM-DD、金额 ¥X万、无信息写"待确认"、不虚构
```

### 4.3 客户数据（实体库管理 + 实体问答）

```
实体库（客户/公司/项目）→ 搜索/筛选/状态切换/跟进 → 静默告警(>30天未跟进) → 看板
项目时间轴：提取 start_date/end_date_est → 按当前日期算进度%（未开始/进行中/已完工）
实体问答（灵魂）：实体卡片向量化 → 检索 TopK + 关联展开 → DeepSeek 汇总
  例："张三什么情况" → AI 总结：归属公司/参加项目/进度/需求/沟通风格 + 来源跳转
关键设计：
- 三栏玻璃 Splitter（iOS 分段控件 + 状态切换）
- Obsidian 式 md 编辑（自绘全屏二级窗口，macOS 交通灯+毛玻璃+动效）
```

## 5. 关键工程设计（面试亮点）

1. **AI 适配层**：`ai/llm.py` 统一封装 DeepSeek（超时/重试/温度），业务代码不直接拼 API
2. **提示词集中管理**：`ai/prompts.py` 锁定全部模板（RAG/纪要/提取/清洗），架构师定规则 AI 遵守
3. **确定性拒答**：检索相似度阈值，不靠模型自觉（可解释、可调参）
4. **人工确认闭环**：AI 只做 80% 重复工作，人做 20% 关键决策（AI提取人工确认原则）
5. **增量不覆盖 + 来源追溯**：实体 merge 保留已有值，每条信息可追到源会议
6. **评估集门禁**：金标问答集自动测命中率，用数字说话
7. **向量检索选型踩坑**：chromadb 跨进程索引崩溃 → 自实现 numpy 余弦（可迁移 Milvus）
8. **脚手架理念**：我定架构/规则/验收，代码由 AI 按规则生成、我校验（Vibe Coding 落地）

## 9. 一句话总结

**用 FastAPI + React 自研一个"可检索、可提取、可问答"的企业 AI 办公助手**：知识库 RAG 带来源拒答、会议信息 R1-R3 提取人工确认闭环、客户实体问答；核心亮点是"确定性拒答 + 人工确认 + 评估集门禁"的可信 AI 设计，以及向量检索踩坑后的自实现方案。
