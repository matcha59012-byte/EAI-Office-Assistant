# 实习期CRM方案_CRM_v2.2 深度分析与功能移植报告

> 版本 V1.0 ｜ 2026-08-17 ｜ 目的：分析实习期 Obsidian CRM 项目的工作流，评估哪些功能可移植到 E-AI Office Assistant，并对照规则标准评估合规性。

---

## 一、实习期CRM方案_CRM_v2.2 是什么

一个运行在 Obsidian 上的**结构化 CRM 自生长知识库系统**（opencode + Obsidian 方案）：

| 模块 | 内容 |
|------|------|
| 01_Clients | 253 个人物画像（软信息 + 5维行事风格 + 项目看法） |
| 02_Projects | 64 个项目资料（背景 + 利益关系图 + 决策 + 争议） |
| 03_Companies | 107 家公司画像（企业信息 + 组织 + 管线 + 运营） |
| 04_Raw | 358 件原始事件（会议纪要 / 邮件 / 聊天记录） |
| _system | 4 个 Agent（digest消化 / lint质检 / insight洞察 / masterfile管家）+ 输出报告 |

**核心哲学（AI提取人工确认原则）："AI 提取，人决策"** —— AI 永不直接写入知识库，先产出审阅报告，人确认后才写入。

## 二、核心工作流分析（我们"之前是怎么操作的"）

### 2.1 Digest 消化管线（最值钱的部分）

```
用户放文件进 04_Raw/（会议/邮件/网页）
   │
   ▼ 自动
R1 文本清洗：补全人名 → 修正拼写 → 去废话 → 按话题分段
   ▼
R2 三路提取：同一份文本同时提取 人物/项目/公司 三种实体
   ▼
R3 增量 Diff：提取结果 对比 已有知识 → 输出变更预览
   ├── 🔄 更新：已有实体补充字段（增量不覆盖）
   ├── 🆕 新增：全新实体
   └── ✅ 无需变更
   ▼
人工确认（@digest 确认写入 / 跳过）
   ▼
写入 01_Clients / 02_Projects / 03_Companies（[[wikilink]] 双向互链）
```

### 2.2 4 个 Agent 分工

| Agent | 角色 | 职责 |
|-------|------|------|
| digest | 消化官 | 扫描 Raw → R1/R2/R3 → 等确认 → 写入 |
| lint | 质检官 | 每日巡检：字段完整度 / 链接完整性 / 过期状态 |
| insight | 洞察官 | 每日简报 + 每周复盘 + 30/60 天静默告警 |
| masterfile | 管家 | 全量快照 |

### 2.3 自生长闭环

```
输入(邮件/会议/网页) → 处理(消化/质检/洞察) → 输出(简报/复盘/告警/Brief) → 回流(新信息回写实体)
```

### 2.4 关键工程原则

1. **增量不覆盖**：已有字段有值就不覆盖，只补充新信息
2. **可追溯**：每条信息带来源（会议/邮件/网页）
3. **不虚构**：提取只能来自原始资料，不能编造
4. **人工确认门槛**：AI 只做 80% 重复工作，人做 20% 关键决策

## 三、可移植到我们项目的功能清单

| 实习期CRM方案 功能 | 移植到 E-AI 哪个模块 | 移植内容 |
|--------------|---------------------|---------|
| R1→R2→R3+人工确认 | **会议纪要** | 会议文字稿 → 清洗 → 提取(摘要/决定/待办/人物/项目) → diff 预览 → 确认入库 |
| 实体模型(人物/项目/公司) | **客户数据** | 客户数据分实体：客户/联系人/公司/项目，互相关联 |
| 30/60 天静默告警 | **客户数据** | "最后跟进时间"字段 + 告警列表（哪些客户超30天没跟进） |
| 增量不覆盖 | 两个模块 | 导入/提取时已有字段不覆盖，只补新值 |
| 来源追溯 | 两个模块 | 每条客户/纪要信息记录 source（文件/导入批次） |
| 看板/洞察 | 客户数据 | 客户总数 / 来源分布 / 静默告警数 / 待跟进清单 |
| AI提取人工确认原则(人确认) | 客户数据 AI提取 | "粘贴文本→AI提取→**预览→确认入库**"，不直接写 |

**注意边界**：移植的是**功能/工作流/数据模型设计**，不是真实业务数据（253 人物/64 项目/107 公司是公司机密，禁止进本项目）。

## 四、规则符合性评估（对照规则标准）

| 规则 | 是否合规 | 说明 |
|------|---------|------|
| AGENTS 0.1 杜绝闭门造车 | ✅ | 复用自己已验证的设计，不重复造轮子；这是"多检索、多拆解开源/自有项目"的正向案例 |
| AGENTS 0.2 文档同步 | ✅ | 增量不覆盖原则与文档同步精神一致；移植前先出本报告 |
| AGENTS 铁律3 必须可运行 | ✅ | 移植后按模块开发，每步测试 3 遍 |
| AGENTS 铁律4 不编造 | ✅ | AI提取人工确认原则"AI 提取、人决策、不虚构"与铁律4完全一致 |
| 禁止夸大交付 | ✅ | 只承诺能跑通的功能，静默告警/看板都做了才写进简历 |
| **IP 红线** | ⚠️ **有边界** | 移植"功能/设计"合规；**移植真实客户/项目/公司数据不合规**（公司机密）。测试必须用脱敏/自造数据 |
| 技术栈锁定 | ✅ | 移植的功能用现有栈实现（FastAPI+SQLite+numpy向量+DeepSeek+React玻璃三栏），不引新重件 |

**结论：功能/工作流移植合规，真实数据移植不合规。按此边界开发即符合全部规则。**

---

## 五、结论

实习期CRM方案_CRM 最值钱的不是 782 条数据，而是三套可复制的"操作系统"：
1. **R1→R2→R3+人工确认** 的 AI 消化管线（→ 会议纪要/客户数据导入）
2. **实体互链 + 来源追溯 + 增量不覆盖** 的数据治理（→ 客户数据模型）
3. **静默告警 + 看板洞察** 的运营闭环（→ 客户数据看板）
