## 1. 从两个老项目学到的核心功能

### 1.1 实习期项目 的语音转文字（ASR）——怎么把 MP3 变 txt
```
MP3/MP4 上传
  → ffmpeg 提取单声道 16kHz 音频（视频则先抽音轨）
  → 大文件按 300s 分段
  → ASR 逐段转写（保中文/英文/人名/项目名/金额/行动项，听不清标 [听不清]）
  → DeepSeek 精炼：Speaker Map（说话人区分）+ 术语纠错 + 逐句一行
  → 输出会议纪要 txt/md（含说话人+内容）
```
关键点：**转写不总结、逐句保留**；说话人区分靠 LLM 精炼；术语表纠错（公司/项目代号）。

### 1.2 实习期CRM方案 的 R1→R2→R3 提取——怎么把 txt 变实体卡片
```
R1 文本清洗：Speaker→人名、修拼写、去废话、标[UNCLEAR]
R2 三路提取（一次prompt同时输出）：
  ├ 人物/客户卡片：软信息 + 行事风格5维 + 项目看法 + 个人主张
  ├ 项目卡片：背景 + 利益相关人图 + 决策 + 争议 + 预算/时间线
  └ 公司卡片：企业信息 + 组织架构 + 管线生态 + 运营模式
R3 增量 diff：与已有实体对比 → 🔄更新/🆕新增/✅无需 → 人工确认 → 写入
```
关键点：**只输出变更、增量不覆盖、来源必追溯、软信息=硬通货、一次prompt三路输出**。

## 4. 技术架构与 API 设计

沿用现有技术栈：FastAPI + SQLite + numpy向量检索 + DeepSeek + React 玻璃三栏。

```
POST /api/meeting/sources              # 上传会议纪要 txt/md（管理员）
POST /api/meeting/transcribe           # 上传 MP3/MP4 → ASR → 产出会议纪要 txt（第①步）
GET  /api/meeting/sources              # 源文件列表
GET  /api/meeting/sources/{id}         # 源文件内容（md渲染）
DELETE /api/meeting/sources/{id}
POST /api/meeting/extract              # {source_id} → R1+R2 → 返回三路实体卡片预览（不入库）
POST /api/meeting/confirm              # {source_id, entity_type, card} → 人工确认 → 写入实体层
GET  /api/meeting/entities?type=       # 实体卡片列表（customer/project/company）
GET  /api/meeting/entities/{id}
GET  /api/meeting/pending              # 待确认提取队列（闭环：扫描后未确认的）
POST /api/meeting/scan                 # 手动/定时扫描源文件夹 → 新文件自动 R1-R3 → 进 pending
```

数据模型（新增 3 张实体表）：
```
meeting_sources:  id, title, content, source_type(txt/asr), status(raw/extracted/confirmed/skipped), created_at
entities:         id, entity_type(customer/project/company), name, fields_json, source_meeting_id, created_at
pending_extracts: id, source_id, entity_type, card_json, status(pending/confirmed/skipped), created_at
```

## 5. ASR 语音转文字方案（核心第一步 ①，用 MiMo，与 实习期项目 一致）

> 已按《AGENTS 底层开发思维》复查：直接复用 实习期项目 已验证的 MiMo ASR 实现（不重复造轮子）。

### 5.1 技术方案（与 实习期项目 完全一致）

| 环节 | 实习期项目 的实现（我们照搬） |
|------|---------------------------|
| 供应商 | **MiMo**（`https://api.xiaomimimo.com/v1`） |
| ASR 模型 | `mimo-v2.5-asr`（或 `mimo-v2.5-audio`） |
| 接口 | OpenAI 兼容 `/audio/transcriptions`（multipart）或 `/chat/completions`（base64 input_audio） |
| 鉴权 | 请求头 **`api-key: xxx`**（不是 Bearer） |
| 支持格式 | **仅 wav/mp3** → 其他格式/视频先用 ffmpeg 转 mp3（单声道 16kHz 64k） |
| 大文件 | 超过阈值 → ffmpeg 按 **300s 分段**，段间等待 30s 防限流 |
| 重试 | 429/5xx 指数退避重试（最多3-5次） |
| 转写提示词 | **逐句转写不总结**：保中文/英文/人名/项目代号/金额/行动项，听不清标 `[unclear]`，说话人用 `[MM:SS] Speaker N:` |
| 说话人精炼 | ASR 后 → **DeepSeek** 做 Speaker Map + 术语纠错 + 逐句一行（照搬 实习期项目 `_refine_transcript`） |

### 5.2 输出（md 文档，对齐 实习期项目 精炼后）

```markdown
# {文件名} 会议纪要转写
## Speaker Map / 说话人映射
## 转写正文
- Speaker 1 (张伟): 客户A项目要优先…
- Speaker 2 (李娜): 报价周五发出…
## 术语纠错记录
```

### 5.3 前置条件
- `.env` 配置 `MIMO_BASE_URL`、`MIMO_ASR_API_KEYS`（从 实习期项目 的 `.env` 复制，**key 不打印/不入库**）
- ffmpeg 已装（imageio-ffmpeg）
- DeepSeek Key 已配（说话人精炼用）

**⚠️ 当前状态**：本助手**暂无 ASR**，M2 将按上述 MiMo 方案实现。

### 5.4 所有会议源文件统一为 md
- 上传 txt → **自动转为 md**（加标题/元信息头，改扩展名 .md）
- ASR 产物 → 直接输出 md
- meeting_sources 一律以 **.md** 存储，前端 md 渲染

## 6. 前端设计（玻璃三栏，与知识库风格一致）

```
左栏「会议纪要」Tabs
  ├ 源文件：上传txt/md + 列表(状态Tag: 待提取/待确认/已入库/已跳过)

  ├ 源文件模式：md 渲染源纪要内容

右栏「AI 工作台」
  ├ 对选中源文件：执行"清洗+提取"
  └ 显示 R1 清洗结果可编辑（人名/术语修正）
```
